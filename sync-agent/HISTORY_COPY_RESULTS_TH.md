24 ตุลาคม 2026 เวลา 18:17 น. (ประเทศไทย)

ผ่านการนำเข้าและตรวจข้อมูลครบชุดตามที่ผู้ใช้ขอ โดยยังไม่เปิดซิงก์จริง ไม่แก้หรือลบข้อมูล Ada จริง และไม่ควบคุมหรือแก้ Shopee automation

ทุกบิลมีเจ้าของรหัสในทะเบียน และทุกบิลมีบรรทัดสินค้า ไม่พบ orphan ในชุดนี้ ไม่ได้นำบิลรหัส0/ลูกค้าทั่วไปหรือบิลไม่มีรหัสมาผูกเป็นประวัติส่วนตัว

ตรวจข้อมูลทุก record ไม่ใช่การสุ่ม: ข้อมูลลูกค้าเดิม101คอลัมน์ที่ไม่ใช่ PIN, รหัสเจ้าของบิล/สาขา/POS/ประเภท/เลขเอกสาร, วันเวลา, ยอดเงิน, สถานะ/อ้างอิงคืนสินค้า และทุกบรรทัดสินค้า SKU ชื่อ บาร์โค้ด รหัสหน่วย ชื่อหน่วย จำนวน จำนวนฐาน ราคา ยอดบรรทัด ตลอดจน raw payload ตรงกับ snapshot ต้นทาง

## หลักฐานว่ารันซ้ำและเริ่มต่อได้

- บังคับหยุด process ตัวนำเข้าจริง PID48364 หลัง commit ลูกค้า1,438และบิล100ใบ พร้อม checkpoint จากนั้นให้ importer อีก process อ่าน checkpoint และทำต่ออีก16,487recordจนครบ ไม่เริ่มสร้างคนหรือบิลใหม่ซ้ำ
- สั่ง replay เต็มชุดอีกรอบ: เปลี่ยนข้อมูลปลายทาง **0แถว**; จำนวน identity และแฮชข้อมูลรวม (รวม updated_at) เท่าเดิม
- เริ่มหลัง checkpoint ครบแล้ว: 0page/0write
- จงใจย้ายบิลเดิมไปอีกรหัสลูกค้า: ถูกปฏิเสธ และข้อมูลปลายทางเท่าเดิม
- ปลอมเจ้าของบรรทัดสินค้าและแก้ payload โดยไม่เปลี่ยน hash: ถูกปฏิเสธ
- เปิด importer สองตัวพร้อมกัน: ตัวที่สองถูกปฏิเสธด้วย worker lock
- จงใจให้แถวหลังใน batch ผิด identity หลังแถวแรกแก้ข้อมูลแล้ว: rollback ทั้งข้อมูลและ checkpoint ไม่ทิ้ง journal ค้าง
- ไม่สร้างบัญชีล็อกอินอัตโนมัติ ไม่เปลี่ยน auth และไม่ให้แต้มย้อนหลัง public users/member_profiles/point_ledger ในสำเนามีแฮชเท่าเดิม
- ข้อมูลลูกค้าและคะแนนใน SQL สำเนาชุดเดิมไม่เปลี่ยนก่อน/หลังงานนี้

รวม **34 integration checks ใหม่ผ่าน** (31การตรวจหลัก + 3การตรวจ transaction/source stability) และ **21 unit tests ผ่าน** แยกจาก31กรณีซิงก์สองทางเดิม

## แยกฐานจริงและฐานสำเนา

- อ่าน AdaAcc จริงบน HQ000 แบบ SELECT เท่านั้น มี timeout/lock timeout/MAXDOP1 และไม่อ่าน PIN ส่งออก100recordต่อpage
- ส่งออกซ้ำอิสระอีกรอบ: customer/header/line files ทั้งสามไฟล์มี SHA256 ตรงกันทุกไฟล์ รวมจำนวนตรงเดิม
- SQL source สำเนาอยู่ในตารางใหม่ `SCCRM_HistorySource` ภายใน `SCCRM_UiSandbox_20261024_142127` บน000 ไม่แก้TCNMCst/บิล/คะแนนของชุดเดิม บัญชีทดสอบเข้าถึงAdaAccจริงไม่ได้และไม่ใช่sysadmin
- PostgreSQL ปลายทางเป็นสำเนาส่วนตัวบนเครื่องพัฒนา `127.0.0.1:55444/sccrm_ada_history_copy` มี schema `ada_history` แยกจาก users/auth/point ledger รหัส/เบอร์ที่ไม่สมบูรณ์จึงเก็บได้ครบโดยไม่บังคับสร้างบัญชีออนไลน์
- snapshot source: `231cb5c4-9a92-442b-ae61-d33f9c0c8560` เก็บ immutable source record และ checkpoint ไม่ทับ snapshot เก่า
- ไฟล์ข้อมูล/รหัสทดสอบอยู่ใน runtime ที่ ignored และจำกัด NTFS ให้บัญชีปัจจุบัน, Administrators และSYSTEM ไม่ได้ commit/push ข้อมูลหรือ credentials
- บริการเดิมบน000ยังhealthyเวลา18:16:47น. workerPID18292 ไม่ได้ restart หรือเปลี่ยน service เดิม
- hash ไฟล์ตั้งค่า Ada ตัวจริงยังตรงค่าเดิม
- หลังเก็บหลักฐาน หยุดเฉพาะ PostgreSQL สำเนาส่วนตัวพอร์ต55444อย่างสะอาด ข้อมูลและcheckpointยังเก็บครบ บริการเดิมบน000ไม่ได้หยุด

## สิ่งที่ได้และขอบเขตที่ยังไม่เปิด

โค้ดเพิ่มอยู่ใน history/: source export แบบอ่านอย่างเดียว, SQL snapshot source, importer แบบ100record/pageและcheckpointที่commitพร้อมข้อมูล, schemaปลายทาง, ตัวอ่านประวัติแยกmember, และชุดตรวจครบทุกrecord

งานรอบนี้เป็นการทดสอบนำเข้าประวัติครบชุดในสำเนา ไม่ใช่การเปิด writer ไปSupabaseจริง และยังไม่ได้ติดตั้งโมดูลประวัติใหม่เข้าบริการ000หรือเปลี่ยนหน้าเว็บจริง บริการเดิมยังทำงานsandboxเดิม การซิงก์ profile/คะแนนสองทางเดิม31กรณียังคงแยกจากการนำเข้าประวัติครั้งนี้

ก่อนเปิดจริงยังต้องติดตั้ง schema/APIอ่านข้อมูลใน backendจริงและสิทธิ์writerเฉพาะส่วน พร้อมทดสอบการเปลี่ยนแปลงใหม่ต่อเนื่อง ไม่ใช้การแก้ชื่อฐานเพื่อลด guard ของชุดทดสอบนี้
