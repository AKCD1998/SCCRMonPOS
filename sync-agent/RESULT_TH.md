# ผลติดตั้งระบบซิงก์เบื้องหลังบน HQ 000

ตรวจล่าสุด 24 ตุลาคม 2026 เวลา 17:39 น. (ประเทศไทย)

ติดตั้งบริการ `SCCRMHQSyncSandbox` บน SERVER แล้ว เป็น LocalService, Automatic (Delayed Start) ทำงาน Session 0 ไม่มี GUI ตามผลตรวจจากเครื่อง 000 ที่ผู้ใช้ส่งกลับมา บริการ PID 18168 และ worker PID 18292 ณ การทดสอบ restart ไม่ต้องจองพื้นที่หน้าจอของ Shopee

## ขอบเขตปัจจุบัน

เป็นระบบทดสอบต่อเนื่องระหว่าง Ada สำเนา `SCCRM_UiSandbox_20261024_142127` กับ PostgreSQL ส่วนตัวที่จำลองโครงสร้าง Supabase (`127.0.0.1:55443/sccrm_hq_sync_copy`) **ยังไม่เชื่อม Supabase จริงหรือเขียน Ada จริง** ไม่มีการอนุมัติให้เปิด production ในงานนี้

ระบบตรวจการเปลี่ยนแปลงทุก 30 วินาที ซิงก์การเพิ่ม/แก้ไขสมาชิกและรายการเพิ่ม/ลดคะแนนสองทาง ใช้ข้อมูลฝั่ง Supabase เป็นหลักเมื่อขัดแย้ง ไม่ลบสมาชิก ไม่ให้ค่าว่างล้างข้อมูลเดิม และไม่เขียนยอดคะแนนตั้งต้นทับ ยอดคะแนนถูกส่งเป็นรายการเปลี่ยนแปลงพร้อมกลไกกันซ้ำ

- ผู้ปฏิบัติบน 000 ตรวจ healthy ก่อน restart เวลา 17:24:18 / 17:24:48 น. และหลัง restart บริการเฉพาะตัวนี้เวลา 17:25:26 / 17:25:57 น.
- SELECT ตรวจซ้ำพบ SQL session `SCCRM-HQ-Sandbox-Worker` บน SERVER ใช้ login `sccrm_ui_20261024_142127` และฐานสำเนาตรงตามกำหนด
- SELECT ด้วยบัญชีทดสอบยืนยัน sysadmin=0; HAS_DBACCESS ต่อ AdaAcc และฐานเก่าสองชุด=0 ทั้งหมด

- SHA256 ไฟล์ AdaIni ของ Ada ตัวจริงตรงกับค่าก่อนทดสอบ
- ไม่พบ service-start-error ปัจจุบัน; ไฟล์ประวัติข้อผิดพลาดเก่ายังเก็บไว้ ไม่ใช่ active error
- ไม่ควบคุมหน้าจอหรือแก้ Shopee, firewall, SQL Server service หรือบริการอื่น

## ปัญหาที่แก้และรายการทบทวน

เครื่อง 000 ซ่อมโฟลเดอร์ว่าง 13 รายการใน cluster ส่วนตัวเดิม แล้วเริ่มบริการสำเร็จ ไม่ได้สร้างฐานใหม่ สาเหตุยืนยันได้จาก Windows PowerShell 5: `@(Get-Content ... | ConvertFrom-Json)` ครอบ JSON array เป็นหนึ่งรายการ ทำให้วนสร้างโฟลเดอร์ไม่ครบ

แก้ Install-TestService.ps1 **ในต้นฉบับฝั่งพัฒนา** ให้เก็บ JSON array ก่อนวนทีละ path และปฏิเสธค่าที่ไม่ใช่ string เพิ่ม regression test ซึ่งรัน loop จริงของ installer บน Windows PowerShell 5 ในโฟลเดอร์ทดสอบส่วนตัว ยืนยันครบ 27 directory และไม่มี directory เกิน ปัจจุบัน npm test ผ่าน 11/11 (10 guards เดิม + regression 1) ไม่ได้นำ installer ใหม่ไปติดตั้งซ้ำบนบริการที่ healthy แล้ว

reviews=4 คงค้าง: สามรายการเป็น fixture ชนิดคะแนนที่ตั้งใจพัก อีกหนึ่งเป็น COPY_RPC_TIMEOUT เก่าตามรายงานเครื่อง 000 ไม่ได้เกิดซ้ำ ไม่มีการลบ fixtures/ประวัติข้อผิดพลาดเพื่อให้ผลดูผ่าน

## การดูแล

โฟลเดอร์เครื่อง 000: `D:\SCCRM-HQ-SyncSandbox-20261024` อ่านไฟล์สถานะใน `status` ได้โดยไม่เปิด runtime ที่มี secrets การหยุด/เริ่มต้องระบุบริการ SCCRMHQSyncSandbox เท่านั้น

การเชื่อมข้อมูลจริงยังเป็นงานขั้นถัดไป ต้องแยกการทดสอบนี้ออกจากการเปิดใช้งานจริง ไม่ลด guard หรือเปลี่ยน login เป็น sa และห้ามนำ snapshot PostgreSQL เก่ากลับมาทับสถานะคู่ฐานสำเนาที่กำลังทำงานอยู่
