# บริการซิงก์แต้ม SCCRM บน HQ 000

ไฟล์ชุดนี้เตรียมการติดตั้งบริการ `SCCRMHQPointSync` แยกจากบริการสมาชิกเดิม
คู่มือนี้ไม่ใช่หลักฐานว่าติดตั้งหรือซิงก์ฐานจริงเสร็จแล้ว ต้องตรวจผลจริงต่างหาก

บริการทำงานเบื้องหลังด้วย `NT AUTHORITY\LocalService`, Session 0,
Automatic (Delayed Start), ไม่มีหน้าต่าง และลดลำดับความสำคัญของงาน
ไม่ต้องเปิด AdaSmart และไม่ควบคุม Shopee, AdaPos, SQL Server หรือบริการสมาชิก

## ขอบเขตแพ็กเกจ

ตำแหน่งบน HQ ต้องเป็น `D:\SCCRM-HQ-LiveSync-20261024\points` เท่านั้น
ใช้ `node.exe` และ `node_modules` เดิมที่โฟลเดอร์แม่ โดยตรวจ pg รุ่น 8.16.3
ตัวส่งแพ็กเกจไม่เขียนทับ runtime ส่วนกลาง ไม่ส่งสคริปต์ admin/operator,
สคริปต์สร้างฐานสำเนา, SQL สำหรับติดตั้ง, ชุดทดสอบ หรือข้อมูลรับรองแบบอ่านได้

`Stage-Service.ps1` ตรวจหลักฐานฐานสำเนา, config ที่ไม่มีรหัสลับ, คอมไพล์ตัวบริการ,
สร้าง manifest แฮชทุกไฟล์และบันทึก digest ของซอร์ส/แพตช์ที่ใช้ ไม่บังคับให้ commit
งานที่กำลังตรวจ หากโฟลเดอร์ปลายทางมีอยู่แล้วจะหยุด ไม่เขียนทับหรือลบของเดิม

ทดสอบแพ็กเกจบนเครื่องพัฒนาก่อนได้ โดยไม่เชื่อมต่อหรือเขียนไฟล์ผ่าน SMB:

```powershell
powershell.exe -NoProfile -File .\points\Stage-Service.ps1 -ValidateOnly
```

หลัง agent หลักตรวจพร้อมแล้ว จึงรันตัวเดียวกันโดยไม่ใส่ `-ValidateOnly`
เพื่อส่งเฉพาะโฟลเดอร์ points ใหม่ไป HQ ขั้นนี้ยังไม่ติดตั้งหรือเริ่มบริการ
ต้องใช้ config ที่ agent หลักเตรียมไว้ใน `points\runtime\config.json`
และตรวจผล `packageReadbackVerified=true` ก่อนส่งงานให้เครื่อง HQ

โฟลเดอร์โปรแกรมอนุญาตให้ LocalService อ่านและรันเท่านั้น ส่วน `runtime` และ
`status` ปิดการรับสิทธิ์จากโฟลเดอร์แม่ ให้เฉพาะ SYSTEM, Administrators,
เจ้าของโฟลเดอร์ และ LocalService โดย LocalService มีสิทธิ์ Modify
ห้ามเปิดสิทธิ์ให้ Everyone หรือแก้ firewall เพื่อแก้ปัญหาการติดตั้ง

## ข้อความสั้นให้ LLM บนเครื่อง HQ — ทำสองขั้น

1. บนเครื่อง `SERVER / HQ 000` เปิด PowerShell ด้วย Run as administrator แล้วรัน:

   ```powershell
   powershell.exe -NoProfile -File 'D:\SCCRM-HQ-LiveSync-20261024\points\Install-Service.ps1'
   ```

   ใช้เฉพาะไฟล์นี้ อย่าสร้าง/หยุดบริการอื่น อย่าเปิด AdaSmart อย่าแตะ Shopee
   ส่งกลับเฉพาะผลสรุปติดตั้งกับ `status\install-result.json` ไม่อ่านหรือส่งรหัสลับ

2. หากขึ้น `bootstrapReady=true`, `healthyPending=true` และ
   `state=awaiting_credentials` ให้แจ้ง agent หลักเพื่อส่งแพ็กเกจข้อมูลรับรองที่
   เข้ารหัสด้วย public key ของบริการ บริการจะลองเริ่มงานใหม่เองประมาณทุก 15 วินาที
   ไม่ต้องกรอกรหัสผ่านในแชต ไม่ต้อง restart โปรแกรมขาย และไม่ต้องติดตั้งซ้ำ
   หาก `bootstrap_pending` ให้ส่งสถานะให้ agent หลักตรวจ ห้ามสรุปว่าใช้งานจริงได้แล้ว

ตัวติดตั้งตรวจชื่อเครื่อง โฟลเดอร์ แฮชไฟล์ สิทธิ์ไฟล์ ชื่อบริการ path บัญชี และ
Session 0 ก่อนรายงานผล หากมีบริการชื่อเดียวกันแต่เป็น path/บัญชีอื่นจะหยุดทันที
ตัวติดตั้งรายงาน `syncReady=false` เสมอ เพราะยังต้องให้ agent หลักตรวจฐานจริง

ถ้า agent หลักเข้าถึง Service Control Manager ผ่านเครือข่ายได้ สามารถใช้
`points\Install-RemoteService.ps1` จากเครื่องพัฒนาแทนขั้นที่ 1 หลังส่งและตรวจแพ็กเกจ
แล้วเท่านั้น ตัวนี้ตรวจ manifest/สิทธิ์ไฟล์ชุดเดียวกัน สร้างเฉพาะบริการชื่อนี้เมื่อ
ยังไม่มี และเริ่มเฉพาะบริการของตน ไม่ใช้ PowerShell ระยะไกล ไม่ส่งรหัสลับ
หากชื่อบริการชนหรือสิทธิ์ไม่พอจะหยุด ไม่แก้บริการอื่นหรือ firewall

## ดูสถานะและความครบถ้วน

```powershell
Get-Service -Name SCCRMHQPointSync
Get-Content -LiteralPath 'D:\SCCRM-HQ-LiveSync-20261024\points\status\service.json' -Raw
Get-Content -LiteralPath 'D:\SCCRM-HQ-LiveSync-20261024\points\runtime\status.json' -Raw
```

`Running` หมายถึงตัวบริการเริ่มได้ ไม่ได้ยืนยันว่าข้อมูลซิงก์สำเร็จแล้ว
ตรวจเวลาสังเกตข้อมูลล่าสุด, ครบห้าฐาน, สาขาที่เปิดส่งจริง, คิวส่งและเหตุผลพักตรวจ
รวมทั้งข้อมูลปลายทางจริงตามสมาชิกที่ agent หลักกำหนด ไม่ใช้ลูกค้าทดสอบปนฐานจริง

หากแหล่งข้อมูลออฟไลน์หรือเก่าเกินขอบเขต ระบบพักการเผยแพร่ยอดกลางแทนการรวม
ข้อมูลไม่ครบ เวลาเดิมของ cache ยังคงอยู่และไม่แสดงเป็นยอดใหม่ที่พร้อมใช้
คิวไม่หายเมื่อเริ่มบริการใหม่ งานส่งที่มีปัญหายังคงสถานะแยกปลายทาง
บริการสมาชิก/ประวัติซื้อเดิมและ Shopee ยังคงเป็นคนละบริการ

แต้มซื้อและการใช้แต้มยึด Ada ส่วน SCCRM อ่านและแสดงผล ไม่คิดแต้มซ้ำเอง
ก่อนส่งกลับปลายทาง receiver ตรวจยอดท้องถิ่นโดยตัดเฉพาะรายการปรับยอดที่
receipt ของฐานนั้นพิสูจน์ได้ ส่วนยอดกลางตัดรายการปรับที่พิสูจน์ได้ทั่วทุกฐาน
รวมสำเนาที่ถูกส่งต่อด้วย จึงไม่นับการปรับยอดย้อนกลับเป็นแต้มซื้อใหม่

หากพบว่า Ada ส่งสำเนารายการปรับยอดข้ามฐาน ระบบจะพักสมาชิก/กลุ่มนั้นให้ตรวจสอบ
แทนการส่งรายการชดเชยสวนกลับ ซึ่งอาจกลายเป็นการปรับขึ้นลงวนไปมา ยอดวิเคราะห์
จากรายการเดิมยังเก็บอยู่ แต่ยอดที่พร้อมใช้และงานส่งของกลุ่มนั้นจะถูกพักไว้

หากยอดยกมาเปลี่ยนหลังบันทึก baseline หรือรายการเดิมเปลี่ยนเป็นประมวลผลแล้ว
ระบบพักสมาชิก/กลุ่มที่เกี่ยวข้องเพื่อทบทวน ไม่เดาว่าการปิดงวดของ Ada ควรถูกรวม
อย่างไร ไม่ลบหรือเขียนทับข้อมูลลูกค้าและรายการแต้มเดิม

## พัก หยุด และ rollback เฉพาะส่วนแต้ม

พักการทำงานโดยเก็บบริการและคิวไว้:

```powershell
Set-Content -LiteralPath 'D:\SCCRM-HQ-LiveSync-20261024\points\runtime\pause.request' -Value 'operator-pause'
```

งานที่เริ่มแล้วอาจต้องจบช่วงปัจจุบันก่อนพัก ตรวจสถานะ `paused` จากไฟล์สถานะ
หากต้องหยุดบริการนี้ให้รันเฉพาะ:

```powershell
Stop-Service -Name SCCRMHQPointSync
```

ห้ามใช้คำสั่งหยุด node ทั้งเครื่อง, SQL Server, AdaPos, Shopee หรือบริการสมาชิก
ตัว host ควบคุมและหยุดเฉพาะ process/job ที่ตนสร้าง

การ rollback เริ่มจากหยุดบริการนี้และคงคิว, receipt, mapping, baseline และ audit
ทั้งหมดไว้ ไม่ลบลูกค้าหรือรายการแต้ม ไม่ย้อนยอดด้วยการแก้ตารางเดิม
หากต้องแก้ยอดหลังตรวจเหตุผิดพลาด ให้ agent หลักจัดทำรายการชดเชยที่ตรวจสอบได้
การสลับรุ่นโปรแกรมต้องมีแพ็กเกจที่ผ่านการตรวจใหม่ และไม่เขียนทับขณะบริการทำงาน

กลับมาทำงานหลังตรวจพร้อมแล้ว โดยนำเฉพาะ `pause.request` ออกและรัน:

```powershell
Remove-Item -LiteralPath 'D:\SCCRM-HQ-LiveSync-20261024\points\runtime\pause.request' -ErrorAction SilentlyContinue
Start-Service -Name SCCRMHQPointSync
```

ขั้นนี้ลบเพียงไฟล์สั่งพักของบริการ ไม่ลบข้อมูลลูกค้า แต้ม คิว หรือประวัติใด ๆ
ต้องตรวจสถานะและผลปลายทางอีกครั้งก่อนรายงานว่าเปิดใช้งานสำเร็จ
