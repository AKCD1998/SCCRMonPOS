# QR จอลูกค้าและการอัปเดตแบบเลือกติดตั้ง

รุ่นเริ่มต้น: SCCRMonPOS 1.1.0.0 บน .NET Framework 4.8

## สมัครสมาชิกสองวิธี

กด `Ctrl+Alt+Q` หรือเปิดจาก System Tray แล้วกด `+ สมาชิกใหม่`:

1. **พนักงานสมัครให้** — เปิดฟอร์มชื่อ/เบอร์เดิม เชื่อม Supabase เดิม
2. **ลูกค้าสแกนสมัครเอง** — เลือกจอลูกค้า แล้วกดแสดง QR

จอลูกค้าแสดง QR เปิด `https://sc-official-website.onrender.com/join` เต็มจอ
พนักงานกดปิดเองได้จากปุ่มกลางด้านบนของจอแคชเชียร์ หรือเมนู System Tray
QR ไม่ปิดเองเมื่อลูกค้าสมัครเสร็จและไม่แสดงข้อมูลส่วนตัวบนหน้าจอ
หลังสมัคร พนักงานค้นหาสมาชิกด้วยเบอร์หรือชื่อในฐานเดียวกันได้

จอแคชเชียร์มีแสงขอบจอสีน้ำเงิน–เหลืองเคลื่อนไหวเฉพาะตอนแสดง QR
แสงเป็นหน้าต่างบาง ๆ สี่ด้านที่ใช้ layered alpha, WS_EX_TRANSPARENT,
HTTRANSPARENT และ WS_EX_NOACTIVATE ไม่มีหน้าต่างรับคลิกครอบพื้นที่กลางจอ
เฉพาะปุ่ม “ปิด QR จอลูกค้า” ที่รับคลิกเมาส์ โดยไม่เปลี่ยน keyboard focus
หลังแสดง QR หน้าสมาชิกจะย่อลงเพื่อให้ใช้โปรแกรมขายที่อยู่ข้างใต้ได้
เมื่อปิด QR ทั้งแสงและปุ่มหาย จอลูกค้ากลับไปเห็นหน้าต่างเดิม

Windows ต้องอยู่ในโหมด **ขยายจอภาพ (Extend)** และเห็นจอแยกอย่างน้อยสองจอ
เลือกจอที่หันไปทางลูกค้าจากรายการจริง โปรแกรมจำ device name ของจอ
โปรแกรมไม่ย้ายหน้าต่าง AdaPos และไม่แก้ฐาน AdaAcc
วิธีส่งคลิกผ่าน layered window อ้างอิง [Microsoft Window Features](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)
การเปลี่ยนการจัดจอขณะเปิด QR จะปิด QR เพื่อให้เลือกจอใหม่ได้อย่างปลอดภัย
Hotkey ใช้งานสมาชิกได้แม้ปิด AdaPos watcher ไว้

## อัปเดตโดยสมัครใจ

- แอดมินใช้คำสั่งปล่อยรุ่นเพื่อเปลี่ยนประกาศส่วนกลางบน GitHub
- เครื่องที่มีรุ่นรองรับแล้วตรวจประกาศหลังเปิด 15 วินาที และทุก 5 นาที
- แต่ละเครื่องแจ้งเตือนผ่าน System Tray และลิงก์ด้านล่างหน้าสมาชิก
- พนักงานกด **อัปเดตและเปิดใหม่** หรือ **ภายหลัง** ได้ รุ่นเดิมยังใช้ได้
- ไม่มีการดาวน์โหลด EXE, ติดตั้ง, ปิดโปรแกรม หรือบังคับรุ่นจากการตรวจตามเวลา
- แจ้งซ้ำได้หลัง 24 ชั่วโมง เครื่องออฟไลน์ตรวจอีกครั้งเมื่อเชื่อมต่อ
- ต้องปิดหน้าสมาชิกและ QR ก่อนติดตั้ง เพื่อลดการรบกวนงานที่กำลังทำ
- ตัวช่วยรอ SCCRMonPOS ปิดเอง ไม่ฆ่าโปรเซส และไม่ปิด AdaPos
- ตรวจ RSA-SHA256 ของประกาศและขนาด/SHA-256 ของ EXE ก่อนเปลี่ยน
- เปลี่ยน EXE แบบ atomic เก็บไฟล์เดิมใน `data/updates/backups/`
- ไม่แทน `.exe.config`, `SCCRMonPOS.secrets.config`, session, watermark หรือข้อมูลอื่น
- ถ้าการเปิด EXE ใหม่ล้มเหลวทันที จะคืน EXE/receipt เดิม ไม่มี health-check
  สำหรับ bug ที่เกิดหลังเปิดสำเร็จ ให้แอดมินประกาศรุ่นก่อนหน้าเพื่อย้อนกลับ

รุ่นเก่าที่ไม่รองรับระบบอัปเดตต้องติดตั้งชุดเริ่มต้นด้วยตนเองครั้งแรกก่อน
ระบบแจ้งอัปเดตไม่เพิ่มการตรวจ minimum version ที่ backend
เครื่องรุ่นเก่าและรุ่นใหม่จึงใช้ API สมาชิกเดิมร่วมกันได้
การย้อน EXE ไม่ย้อนข้อมูลสมาชิกหรือฐานข้อมูล

## คำสั่งแอดมิน

เครื่องแอดมินต้องมี Git, GitHub CLI ที่ลงชื่อเข้าใช้แล้ว, Visual Studio MSBuild
และ .NET Framework 4.8 targeting pack ก่อนปล่อยจริงต้อง review, commit และ push
source ที่ต้องการไป `master` ให้ตรงกับ `origin/master` และ checkout ต้องสะอาด
คำสั่ง publish จะ commit เฉพาะ `releases/stable.json` ที่มันสร้างเอง

กุญแจส่วนตัวที่ใช้ลงลายเซ็นถูกเก็บนอก repo ด้วย Windows DPAPI ของบัญชีแอดมิน
ค่าเริ่มต้นคือ `%APPDATA%/SCCRMonPOS-Admin/update-signing-key.dpapi`
public key อยู่ใน `SCCRMonPOS/Assets/UpdatePublicKey.xml` และฝังใน EXE
เก็บสำรองกุญแจและ Windows profile ในที่จัดเก็บของแอดมินที่ปลอดภัย
ห้ามสร้างกุญแจใหม่ทับเพื่อแก้ปัญหาปล่อยรุ่น เพราะเครื่องเดิมจะตรวจลายเซ็นไม่ได้
ใช้ `Initialize-UpdateSigning.ps1` เฉพาะการตั้งระบบใหม่ครั้งแรกเท่านั้น

เตรียมไฟล์เพื่อตรวจโดยยังไม่เผยแพร่:

```powershell
./tools/Publish-PosRelease.ps1 -ReleaseId pos-1.1.0 -Version 1.1.0 -NotesFile ./docs/release-notes-1.1.0.md -PrepareOnly
```

การเตรียมจาก source ที่ยังไม่ commit จะมี `sourceDirty: true` เพื่อใช้ตรวจในเครื่อง
ให้ใช้ release id ใหม่และ source ที่ review แล้วในการปล่อยจริง

ปล่อยรุ่นจริงตามคำสั่งแอดมิน (สร้าง GitHub Release และประกาศให้ทุกเครื่อง):

```powershell
./tools/Publish-PosRelease.ps1 -ReleaseId pos-1.1.1 -Version 1.1.1 -NotesFile ./docs/release-notes-1.1.1.md
```

ย้อนรุ่นที่แนะนำไปยัง release ที่เคยลงลายเซ็นไว้:

```powershell
./tools/Publish-PosRelease.ps1 -RollbackTo pos-1.1.0
```

คำสั่งย้อนกลับจะเปลี่ยนประกาศและแจ้งให้พนักงานเลือกติดตั้ง EXE รุ่นนั้น
ไม่ต้องลบประวัติ Git หรือ force-push หากต้องแก้ source ให้ใช้ git revert
แล้ว review/build/release ตามปกติด้วย release id ใหม่
ถ้าสร้าง release สำเร็จแต่ push ประกาศไม่สำเร็จ ให้ตรวจ Git ก่อนลองต่อ
สามารถเลือก release ที่สร้างไว้ด้วย `-RollbackTo` เพื่อประกาศใหม่ได้

## การตรวจสอบรุ่นนี้

`tools/DesktopFeatureCheck.csproj` ตรวจลายเซ็น/ข้อมูลปลอม, การติดตั้งและคืนไฟล์
เมื่อ launch ล้มเหลว, การย้อนเวอร์ชัน, การคง config/session, จำลองสอง device
ว่าการตรวจประกาศไม่ดาวน์โหลด EXE, ดาวน์โหลดเฉพาะเครื่องที่กด, การอ่านประกาศ
ที่ไม่พร้อมใช้ และ window style/alpha ของ overlay รวมการเรียก Win32 layered
window นอกพื้นที่มองเห็น ภาพ preview มาจาก component จริงของโปรแกรม

QR ใน resource และภาพ render ถูก decode กลับมาตรงกับ URL สมัครจริง
การทดสอบนี้ไม่แทนการลองจอคู่/เครื่องสแกน/สเกล DPI บน POS แต่ละรุ่น
ยังไม่มีการติดตั้งหรือเปลี่ยนไฟล์บนเครื่อง POS ระยะไกลในการพัฒนานี้
และจะมีประกาศส่วนกลางจริงเมื่อแอดมินสั่ง publish เท่านั้น
